# Contribute to OSRI

Start with the [short research guide](START_HERE.md). Ask questions and request public resources in [Q&A](https://github.com/Open-Source-Research-Initiative/.github/discussions/new?category=q-a). Share topic proposals in [Ideas](https://github.com/Open-Source-Research-Initiative/.github/discussions/new?category=ideas).

Use your preferred language. The [browser guide](docs/browser-setup.md) explains sign-in, a first submission, and project setup. You can ask a maintainer to add a source note or table to the repository.

You can contribute a question, source, explanation, review, writing, data work, code, or simulation. A source lead may remain unchecked. A typo needs only a short explanation. Maintainers can help turn a suggestion into a change.

## Choose a first contribution

| Your interest | A useful first task |
| --- | --- |
| Getting started | Ask a question, explain an unclear passage, or correct a link. |
| Subject knowledge | Help define a research question or examine an interpretation. |
| Literature | Find a source, verify a citation, or extract evidence using the project method. |
| Data and methods | Check data, reproduce a calculation, write code, or test a model. |
| Writing and review | Edit a passage, check a method, or review a claim against its evidence. |
| Languages and community | Translate a page, review a translation, request a resource, or help another contributor. |

Choose a small task from a [research project](projects/README.md), or describe what you can help with in Q&A. Include the question, source, or proposed change. A maintainer can help with Git and the next step.

If no project is ready for you, [offer help](docs/find-help.md#find-collaborators-or-offer-help) or [try the first source comparison](START_HERE.md#a-first-task-without-code). You do not need to start a whole study.

Already doing research? See [how to bring an existing project](projects/README.md#bring-an-existing-project).

## Submit and receive credit

Follow [OSRI-0.1.0](governance/contribution-standards.md). State the task, evidence, checks that occurred, and review still needed. Record material agent assistance. A person remains responsible for accepting changes and authorizing publication.

Use issues for agreed tasks and pull requests for changes. Keep links to the discussion and relevant research project. For confidential matters, contact [Cole](mailto:cole.lyons@pennmedicine.upenn.edu).

Use the [help and review guide](docs/find-help.md) to request a collaborator or reviewer. Ask who is responsible for the next action. Discuss contribution roles and authorship as work develops. Confirm credit before submission.

Follow the guides for [writing](governance/writing-style.md), [translation](governance/translation.md), and [visual identity](governance/visual-identity.md).

Accepted work can be recorded on the [contributor activity board](community/ACTIVITY.md). Ask a maintainer to add the record and your chosen public credit name.
