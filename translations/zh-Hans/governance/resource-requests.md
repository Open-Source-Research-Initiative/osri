# 申请研究资源

> **待审核译稿（draft）** · 译者：Codex · 人工审核：待定 · [英文参考原文](https://github.com/Open-Source-Research-Initiative/osri/blob/a7b0e61f1a33fece8873bc9574d747da0a7615b6/governance/resource-requests.md)

无法自行获取资源时，可按本流程申请文章、数据集、数据库查询、标准、软件或其他研究资源。Cole 或其他指定管理员可以尝试通过大学权限、图书馆服务、提供方申请或开放替代资源提供帮助。提出申请不保证资源可用，也不授予访问权。

## 先提交简短申请

在 [OSRI 问答区（Q&A）](https://github.com/Open-Source-Research-Initiative/.github/discussions/new?category=q-a)发帖，标题使用 **Resource request: [简短标题]**。可参考[公开申请模板（英文）](../../../templates/resource-request.md)。提供引用或公开资源链接、项目或研究问题，以及所需内容。简短说明即可开始；管理员会协助补全信息。无法使用 Discussions 时，可以使用现有的 [issue 队列](https://github.com/Open-Source-Research-Initiative/.github/issues)。

只发布可以公开的信息。不要在帖子或附件中放入受限文件、个人数据、保密研究计划、非公开条款或凭据。已商定的任务可用 issue 跟踪，并关联讨论。`.github` 论坛仍是共同的公开入口。

## 私下申请

需要私下协调时，给 [Cole](mailto:cole.lyons@pennmedicine.upenn.edu) 发邮件。可以直接联系，无须先公开发帖或新建 issue。如果使用公开帖子，不要在其中提及敏感资源或项目。发送受限材料前，先商定交付方式与受控存储位置。商定后，可以使用[私下申请模板（英文）](../../../templates/resource-request-private.md)。不要发送凭据。

## 管理员流程

每项申请指定一位人类资源管理员，记录状态、下一步行动与下次更新日期。即使咨询了图书馆员或提供方，该管理员仍负责跟进。公开更新仅包含可公开的元数据。保密检查和交付细节保存在商定的非公开记录中。

| 状态 | 行动与记录 |
| --- | --- |
| 已提交（Submitted） | 登记申请，并确认其范围。 |
| 已初步评估（Triaged） | 注明管理员，明确用途、使用者、所需版本或子集、时间与费用。检查是否有合适的开放替代资源。 |
| 访问核查（Access check） | 检查实际资源条款，以及机构权限是否覆盖拟议用途。向图书馆、提供方或数据管理者澄清不明确的条件。记录获准的使用者、工具、存储、传输、分析与输出条件。 |
| 已提供资源或替代方案（Fulfilled or alternative supplied） | 提供获准的副本或摘录，安排获准的直接访问，或执行获准的查询或分析并交付允许的输出。记录版本、来源、交付日期与相关限制。替代资源必须明确标注。 |
| 已关闭（Closed） | 确认收到资源，或记录结果与尚存的研究局限。记录后续保留、到期、删除或报告义务及负责人。 |

条款不明时，维持访问核查状态，并确定下一步。只有适用条款或提供方的实际决定排除了访问或使用，才标记为 **denied**。无法取得资源时，记录 **unavailable** 及已做的检查；不要把不确定性描述为禁止。申请者也可以撤回请求。

## 访问权限必须符合用途

大学身份验证只说明用户的访问渠道，本身不意味着可以向 OSRI 协作者再分发材料。管理员应核查接收者和拟议用途是否被许可覆盖，包括摘录与派生输出。不得共享凭据或绕过登录控制。不得假定订阅允许批量导出、自动获取或文本挖掘，也不得假定可以向智能体或外部服务发送受限材料。在提供材料前，记录拟用工具与服务的使用许可。

受控数据集可能要求数据使用协议、指定使用者、培训或其他批准、安全分析环境，以及输出审核。管理员负责落实适用要求和获准的交付方式。如果文件不能迁出，可以考虑在数据所在地开展获准的分析。产生费用前必须取得授权。即使原始材料受限，仍应在项目中保留允许公开的方法、引用与访问说明。

不同资源和机构的条款各不相同。例如，[CMU 图书馆使用政策（英文）](https://www.library.cmu.edu/policies/statement-electronic-resources-use)区分许可访问、下载、再分发、挖掘与向 AI 上传材料。[NIH dbGaP 数据使用认证（英文）](https://grants.nih.gov/policy-and-compliance/policy-topics/sharing-policies/accessing-data/certification-agreement)要求受控数据用于获准的使用者、研究与安全条件。这些例子不决定其他机构的权限。即使文章可以免费阅读，也应检查该文章的许可；[PMC 版权说明（英文）](https://pmc.ncbi.nlm.nih.gov/about/copyright/)解释了这一点。

寻找许可合适的开放数据集、作者手稿、预印本、仓库副本或作者提供的材料。替代资源应适合研究问题。若文章版本或数据集不同，应记录差异。在获准的访问与用途适合研究时，机构资源仍然有价值。
